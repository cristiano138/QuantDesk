### 三条口径决定（写清楚，避免以后当 bug 改回去）

1. **设置切换与提交的生效边界 = 那次原子占位。** 占位前切回模拟盘 → 原确认作废（REJECTED，
   不会替用户新建模拟成交）；占位后单子已经是 `submitted`，此时再切开关只影响下一单。
2. **`confirm_timeout_s=0` 只表示「不起超时线程」，不是「关掉过期校验」。** 没有写截止时间的
   单只有两种来源：测试里显式设 0、或老库补列的默认值；两者在确认时分别按「无截止时间」和
   「判据缺失 → 作废」处理，生产默认 10s 走完整判据。提示词第 262 行要求的正是这条区分。
3. **断线只记「结果不明」，不自动重发。** 外部券商与 SQLite 之间不宣称 exactly-once：
   恢复流程看 `result_uncertain` 与 `submitted` 单边挂账，交给对账（K02/K03/K11 的作用域与
   账本合同）而不是再投一笔真钱委托。
