## 一、产品定位与商业形态

| 维度 | 口径 |
|---|---|
| 产品 | Windows 单机本地 A 股量化交易工作台（策略编写→回测→模拟盘→实盘一体化） |
| 用户 | 已有券商账户、能自己写 Python 或愿意学策略语法的个人量化投资者；小型私募/工作室的单机研究台 |
| 交付物 | 安装包（或源码 + `启动.bat`）+ 本地数据目录 + 文档（README/接入卡/运维手册） |
| 收入模式 | 软件授权（单机买断 / 按年订阅）；**数据源与交易通道费用由用户自付**（Tushare 积分、iFinD 订阅、券商权限），本产品不转售行情、不做数据分发 |
| 明确不做 | 服务器托管、云端策略执行、代客理财、收益承诺、投顾建议、绕过券商权限或监管报备 |
| 免责红线 | 「不构成投资建议，实盘可能损失本金；程序化交易须按券商与交易所要求报备；easytrader 类非官方接口风险自担」——对外分发时不得删除（宪法第 9 条配套） |

**与主流股票软件的"结合"在本产品里有三种形态，缺一不可：**

1. **数据通道**（读）：miniQMT、通达信、同花顺 iFinD、AKShare、Tushare——用户在客户端里看到的价格，我们的回测与策略用的是同一口径；
2. **交易通道**（写）：miniQMT（主力）、掘金、同花顺客户端 GUI 自动化（默认禁用）——下单经服务端三道闸，回报与本地库周期对账；
3. **工作流互操作**（不依赖任何权限）：自选股/信号 ↔ 通达信自定义板块文件（`.blk`）、同花顺/东方财富导入格式；策略条件 ↔ 通达信/同花顺「公式管理器」的条件选股公式文本。
   第 3 类是 v1 方案完全没有的内容，也是商业上最轻的落地路径：**用户不必开通 QMT 权限，也能把 QuantDesk 的选股结果放进他每天用的软件里。**

## 二、主流股票软件接入矩阵

### 2.1 通道注册表（真实状态，取自 `describe_adapters()`）

| 注册名 | 类型 | 中文标签 | 能力 | 可选依赖 | 就绪判据 | 默认 |
|---|---|---|---|---|---|---|
| `qmt_xtdata` | 行情 | miniQMT 行情（xtquant） | 历史/实时 tick/实时 bar | `xtquant` | 券商开通 QMT + miniQMT 登录 | 启用 |
| `tdx_aidata` | 行情 | 通达信（官方 SDK / pytdx） | 历史/实时/分笔 | `TdxAiData` **或** `pytdx`（择一） | 任一依赖安装即可 | 启用 |
| `ths_ifind` | 行情 | 同花顺 iFinD（付费） | 历史/财务/实时/分笔 | `iFinDPy` | 商务开通 + 私有 whl + 凭据 | 启用 |
| `akshare` | 行情 | AKShare（公开接口） | 历史/财务 | `akshare` | 免注册（受反爬限速） | 启用 |
| `tushare` | 行情 | Tushare Pro | 历史/财务 | `tushare` | token 已配置 | 启用 |
| `federated` | 行情 | 组合适配器 | 动态聚合子源 | — | services 层唯一行情入口（ADR-4） | 启用 |
| `paper` | 交易 | 内置模拟撮合 | 模拟全功能 | — | 无前置（`is_paper=True`） | 启用 |
| `qmt` | 交易 | QMT/miniQMT 实盘 | 下单/撤单/查询/回报 | `xtquant` | QMT 权限 + userdata + 资金账号 | 启用 |
| `gm` | 交易 | 掘金量化终端 | 下单/撤单/查询/回报 | `gm` | 掘金终端 + token + 账户 | 启用 |
| `easytrader` | 交易 | 同花顺客户端 GUI 自动化 | 下单/撤单/轮询查询 | `easytrader` | 客户端锁版本 + 手工启用 | **默认禁用** |

未装 SDK 的通道不会让应用崩，也不会被伪装成可用：注册表如实上报 `status=unready` + `missing=[缺哪个模块]`，实例化时抛带安装引导的结构化错误（`adapters/base/optional.py`）。

### 2.2 通道元数据合同（新增通道必须声明）

```python
class SomeFeed(DataFeedAdapter):
    name = "..."              # 注册名，全局唯一
    label = "中文名"           # UI 展示
    prereq = "一句话说清用户要做完哪一步才能用"   # UI 接入向导直接展示
    requires = ("sdk_module",)      # 可选依赖（惰性导入，不进 pyproject）
    requires_any = False            # True=任一依赖可用即就绪（通达信双传输层）
    official = True                 # False=UI 红字「非官方接口，稳定性低」
    default_enabled = True          # False=注册表源头跳过，交易 API 不可见
    enable_flag = "enable_xxx"      # default_enabled=False 时对应的 Settings 布尔字段
```

**为什么这套元数据是商业必需而非工程洁癖**：通道的"能不能用"取决于用户机器上的客户端与权限状态，这是**运营问题不是编译问题**。把它做成数据而不是散落在 if-else 里，接入向导、状态灯、故障引导、以及"未开通就自动降级到免费源"的销售话术才能同一份事实源驱动。

### 2.3 通道路由与降级（`settings.feed_priority_*`，可配置不硬编码）

| 用途 | 默认优先级 | 降级语义 |
|---|---|---|
| 历史 K 线 | `qmt_xtdata,tushare,akshare` | 查询型，逐个降级；本地 Parquet 命中不外呼 |
| 实时行情 | `qmt_xtdata,tdx_aidata` | **主源单一，断线不换源**（ADR-5：两套 tick 口径混喂策略会产生错误信号） |
| 财务数据 | `ths_ifind,tushare,akshare` | 查询型降级链 |

交易通道由 `settings.broker_channel` 单选（`paper` / `qmt` / `gm` / `easytrader`），由 ChannelHub 每次下单动态解析，改设置即生效。

### 2.4 已知的软件接入风险点（写进代码注释与接入卡，不靠人记）

| 通道 | 已实装的对策 |
|---|---|
| miniQMT | 回调线程只入队；交易/行情两条回调线程分离；`order_remark=本地 order_id` 作回报锚；`session_id` 每次启动唯一；断线 fail-closed 可探测；重连重放订阅 |
| 通达信 | SDK 连接对象非线程安全 → **单工作线程串行队列**（`max_workers≠1` 直接抛错）；无官方复权 → 请求 FORWARD 时抛 `FeedCapabilityError` 而**不伪造**；pytdx 轮询合成实时（默认 3s） |
| iFinD | 登录态与请求互斥锁；会话失效只重登 1 次；配额计数 + 三层缓存（进程内/Parquet/TTL），超配额只读缓存不再消耗 |
| 掘金 | SDK 交易函数必须在其事件循环线程内调用 → 专用终端线程 + 请求队列投递，调用方带超时 |
| easytrader | GUI 自动化串行；无回调 → `poll()` 快照 diff；控件找不到 → 截图落 `data/logs/easytrader/` + 结构化异常指向"锁版本"；默认禁用 |
| AKShare | 东财 push2 限流实测触发过 → 熔断（5/15/30min 递增冷却，冷却期不触网）；**qfq 口径存在源级日收益分离（10/10 标的复现）**，不作精确回测基准 |

## 三、运行时架构（v2 新增的五个部件）

v1 方案的适配器层是"文件存在即接入"，本轮补上了让文件真正被用起来的中枢：

```
                     ┌─ settings.feed_priority_* ─┐
UI(REST/WS) ── services ── ChannelHub ────────────┴─→ FederatedFeed ─→ 各行情通道
                     │        (按名装配/缓存/fail-closed 原因留痕)
                     ├─ RealtimePump  订阅上行→行情下行→历史种子→bar 聚合(dt 取周期起点)
                     ├─ RiskGate      订单唯一咽喉；live 通道经 hub.live_broker() 动态解析
                     ├─ ReconcileService  周期全量快照 vs SQLite，差异落库 + RISK 广播
                     ├─ LogSink       LOG/RISK 事件批量落库（run_log 表，可检索）
                     └─ core.secrets  DPAPI 凭据保险库（只写不读，掩码回显）
```

### 3.1 本轮接通的关键断点（v1 遗留）

1. **策略下单意图从没进过闸门**：`ctx.buy()` 经 IPC 上行的 `order_intent` 过去只被广播成事件，从未 `RiskGate.submit()`。现在 `strategy_mgr._route_intent()` 是唯一入口，非法意图（碎股/超区间）被闸拒并落库可查原因。
2. **`ctx.subscribe()` 没人接**：现在订阅登记进实时泵，行情按标的扇出到对应策略子进程。
3. **实时代 k 线会把子进程历史缓冲刷满重复行**：泵现在按周期取 **bar 起点**为 dt，子进程侧对同 dt **upsert**——与回测"history 含当前 bar"同语义。
4. **线格式 bug**：`bar_to_dict` 曾用 `str(freq)` 输出 `"Frequency.D1"`，子进程拿到的是脏周期值；现在统一 `.value`。
5. **桌面壳打开是 404**：FastAPI 未做 SPA 静态托管（v1 记录为"已做"）。现在 `/` 与客户端路由回落 `index.html`，`/api/*` 未知路径仍是 404 JSON。
6. **切实盘的确认文本只在前端判**：`curl` 直连即可绕过。现在校验在服务端（`settings_svc`），不带 `confirm` 一律 400。

### 3.2 同构装配表（v2 实况）

| run_mode | DataFeed 装配 | Broker 装配 | 确认流 | 时钟 | 状态 |
|---|---|---|---|---|---|
| `backtest` | HistoricalDataFeed（Parquet 回放） | PaperBroker（bar 撞价，虚拟时钟） | 无 | 虚拟 | ✅ 已验证（e2e + 592 例） |
| `paper` | FederatedFeed（实时主源）+ 历史种子 | PaperBroker（tick 撞价 + 挂单簿） | 无 | 真实 | ✅ 管道已接通，待真实实时源在线验收 |
| `live` | FederatedFeed（实时） | QMTBroker/GmBroker/EasytraderBroker（经三道闸） | **强制** | 真实 | ⚙️ 代码与离线假 SDK 已验证，**待券商权限做在线核对** |

### 3.3 本轮新增架构决策（ADR-6 起）

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-6 | 通道装配收口到 ChannelHub，services 不再 `new` 具体适配器 | v1 里 scheduler 写死 `[AkshareFeed(), TushareFeed()]`、trading 实盘永远 None——装了 QMT 也用不上 | 多一层装配复杂度 |
| ADR-7 | 凭据走 Windows DPAPI 本地保险库，**任何接口不回显明文** | 宪法第 7 条要求"加密存储"，`.env` 明文会被备份/git/截图带走 | 换 Windows 账户/重装系统后需重录凭据（文档已写） |
| ADR-8 | 实时泵是唯一行情扇出点（面板/撮合/策略进程） | 多点订阅会重复向主源挂订阅，引用计数失效 | 泵是单点，崩了整条实时断——由状态灯与 watchdog 暴露而非隐藏 |
| ADR-9 | 策略订阅时回灌本地日线尾部 250 根作历史种子 | 否则 dual_ma 启动后要等够周期才第一次决策，"三模式同构"名不副实 | 首次订阅多一次 Parquet 读与 250 条 IPC 消息 |
| ADR-10 | 对账同时校验通道自带不变式（cash+mv≈total） | GUI 自动化/SDK 字段映射错误会在这里先炸出来，比"和昨天比"更能当报警用 | 误报需人工判读（宁可误报，D22 口径） |
| ADR-11 | 默认禁用通道从注册表源头跳过 | 宪法第 9 条"不是前端藏按钮"；`get_adapter_class`/`list_adapters` 都不可见，只有面板可读 | 启用需设置页确认文本 + 热生效 |
| ADR-12 | 选股规则"一份定义，两种编译"（客户端公式 / 本地求值） | 用户在通达信里看到的信号必须和我们回测的是同一条件，否则互操作就是误导 | 规则类型受限于可翻译的指标族 |

## 四、安全与合规：服务端强制清单

**验收方式统一：绕过前端，直接用 HTTP 客户端打接口，行为必须仍然正确。**

| 项 | 强制点 | 证据 |
|---|---|---|
| 闸① 全局模拟盘开关 | 每次 `submit()` 动态读配置，不缓存 | `tests/test_settings.py`（开关热切即时影响路由） |
| 闸② A 股规则校验 | T+1 可用/整手/委托价∈涨跌停（复权价兜底拦截）/资金/单票上限/日委托数 | `tests/test_riskgate.py` 17 例 + 本轮 `test_realtime_loop.py` 碎股被拒 |

| fail-closed | 通道缺位/未启用/缺凭据/连不上 → 一律拒单不降级；实时断线不静默换源 | `tests/test_channels_hub.py` 14 例 |
| 危险开关确认文本 | **服务端**校验（`simulation_only=false`、`broker_channel≠paper`、`enable_easytrader=true`） | `test_switching_to_live_requires_server_side_confirmation` |

| 凭据 | DPAPI 密文 + 额外熵；只写不读；日志前 4 位 + *** | `tests/test_secrets.py` 8 例（含"换熵解不开""文件损坏给引导"） |
| 先落库后广播 | 订单/成交/持仓/对账差异/运行日志全部先 SQLite 再事件 | `tests/test_paper_trading.py`、`test_reconcile.py` |

**审计四表**：`orders` / `trades` / `positions_snapshot` / `reconcile_diff` / `run_log`（后者两张本轮新增）——重启不丢，事故可回溯，导出即对账材料。

## 五、质量与验证体系

### 5.1 双层验证协议（这是本轮方法论的核心）

主流股票软件的 SDK 无法在开发机/CI 上真实存在，因此每个通道的验证分两段：

**第一段：离线可测层（已自动化，`uv run pytest`）**
- 假 SDK（`tests/mocks/{xtquant,pytdx,TdxAiData,iFinDPy,gm,easytrader}`）按公开接口形状实现，可脚本化注入故障；
- 被测的是**我们自己的代码**：列名/字段归一化、参数映射、状态机、串行化纪律、回调只入队、超时与重试上限、断线可探测、重连重放、脱敏、fail-closed；
- 判据：全部离线用例不打网、不依赖真客户端，任何机器 `uv run pytest` 可复现。当前 **592 passed**（连续两轮，60s 内跑完）。

**第二段：在线核对层（需真实客户端，人工 + 脚本）**
- 每张接入卡（`docs/integration/*.md`）末尾有「在线核对清单」，列出**离线证不了**的 SDK 表面：真实字段名、常量取值、返回值形态、回调触发时机；
- 通到真实客户端后逐项打勾，并跑交叉对数：与已接入任一源误差 ≤ 0.1%（除权日单列），`scripts/verify_sources.py` / `verify_qmt.py` / `dod_d27_align.py` 出报告进 `data/logs/`；
- 交易通道在线验收：只读核对（与券商 APP 人工对比）→ 不成交价限价单 + 撤单 → 全链路 <3s 打点 → fail-closed 演练（拔网线/退出客户端）→ 半日小资金人工确认运行。

**为什么这样切**：把"SDK 口径"和"我们的逻辑"分开，前者出错是接入清单没打勾（可定位、可补），后者出错是回归失败（当场拦住）。混在一起时，实盘第一次下单才会发现两者都在错。

### 5.2 发布门禁（每次发版逐条过）

1. `uv run pytest`（应全绿，`network` 标记默认跳过）；
2. `node_modules/.bin/tsc --noEmit` + `vite build` 零错误，产物由后端静态托管后 `/`、`/channels`、`/interop` 直接访问不 404；
3. `scripts/e2e_v1.py` 全链路剧本通过（数据→回测→模拟盘全天 tick→费用核算→重启恢复→三道闸）；
4. 浏览器遍历全部路由（10 条）与一条真实交互链路，console 零错误——本轮两次白屏级 bug
   （`/api/market/snapshot` 返回 null、`/api/system/adapters` 契约漂移）都只有遍历才能抓到，
   后端用例全绿对此毫无免疫力；
5. 实盘相关：接入卡在线清单已打勾 + 对账零差异 + 报备清单已填并导出；
6. 版本号 + tag + `进度日志.md` DoD 核对表 + `AGENTS.md` 当前状态节更新。

## 六、交付形态与运维

### 6.1 分发

| 形态 | 适用 | 现状 |
|---|---|---|
| 源码 + `uv sync` + `启动.bat` | 技术型用户/二次开发 | ✅ 可用 |
| 单机免环境包（PyInstaller + 前端 dist 内嵌） | 目标客户主体 | ⚠️ 规划 v1.2（见 §7），当前 `启动.bat` 需本机有 uv/Python |
| 安装器（NSIS/Inno）+ 桌面快捷方式 + 卸载 | 商业分发必需 | ⚠️ 规划 v1.2 |
| 代码签名 | 消除 SmartScreen 拦截 | ⚠️ 需采购证书，规划 v2.0 |

生产形态已具备：前端构建产物由 FastAPI 静态托管（运行机不再需要 Node），桌面壳 pywebview 同源加载 127.0.0.1:8787，后端未就绪时壳给引导页而不是白屏。

### 6.2 备份与迁移（有真实坑，必须写进手册）

- 数据全本地：`data/quantdesk.db`（SQLite WAL）+ `data/parquet/**` + `data/logs/**` + `data/exports/**`；
- **`data/credentials.vault` 与 Windows 账户绑定**（DPAPI）：换机器、重装系统、换用户登录后必须重新录入凭据——备份时把这一项标注为"不可跨机还原"，其余可整体拷贝；
- 库结构演进目前是**增量加表**（`reconcile_diff`、`run_log`、`account_state` 均为 `create_all` 自动补建），字段级变更走 `store/db.py` 的 `schema_version` + 手写迁移脚本（规划：把迁移做成带编号的 SQL 序列，v1.2）。

## 九、已知限制（诚实清单，交付前必须让买方读到）

1. **六个主流软件通道的在线核对尚未执行**——QMT 权限、掘金终端、iFinD 试用、通达信 SDK 都不在本机；代码与离线假 SDK 用例已完成，真实口径要按接入卡清单逐项验证。这是"接入完成"与"接入可交付"的分界线，本文档不把它写成已完成。
2. `paper` 模式在真实实时源接上之前，实时驱动只经过 tick 注入等价验证（`scripts/e2e_v1.py`）。
3. 通达信 pytdx 路线是非官方协议实现（社区维护），面板 `transport_official` 会如实区分标注；官方 SDK 路径需申请权限。
4. 互操作层的北交所板块市场位未实测确认——导出时**默认跳过并显式告知**，不猜一个前缀冒充正确。
5. M1 交叉对数（AKShare vs Tushare）与 D27 因子级校验仍待 Tushare token：配置 `QUANTDESK_TUSHARE_TOKEN` 或凭据保险库 `tushare.token` 后重跑 `scripts/verify_sources.py` 即可，无需改代码。
6. 免安装包与安装器（v1.2 第 1 项）未产出——当前交付形态要求目标机有 uv/Python。
7. 策略日志检索为结构化事件表，不含策略 stdout 原文（子进程 print 不进 IPC）；需要的话在 `BaseStrategy` 侧加显式 log API。
8. **缺口检测看不穿"内部空洞"**：`data_store.batch_download` 按 `range_of`（首/末日期）判断是否已覆盖，
   序列中间缺一段（如某半年）时补洞请求会认为"已有"而只回极少行数。本轮一次测试污染事故里实测复现
   （回写 134 根真实日线后再补 2020-01~06，只回了 8 行）。后果是**静默数据洞**，直接污染回测与信号。
   修法已排进 v1.2 第 7 项：按交易日历比对实际 dt 集合，输出缺失日期清单并可定向补齐。
