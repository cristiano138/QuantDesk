## 六、K03：原子结算、幂等与资金/持仓预占

把同一次模拟成交的成交行、费用、资金、订单累计成交与持仓放在同一事务。计算可用新快照，提交成功后再应用内存变化并广播；失败恢复内存或从已提交快照重载。外部网络调用不持有数据库写事务。

请求幂等与回报去重分别实现：

- 调用方生成请求键；服务端按稳定作用域和请求键设置唯一约束。相同请求返回原结果；相同键不同参数返回冲突。前端超时重试保持同一键。
- 券商回报以账户、通道、券商成交号去重；回报无稳定标识时明确处理合同，不能自造一个不可靠的键。
- 下单、成交、撤单、拒单、确认失效、超时和重启共同维护资金/可卖量预占。部分成交只释放或消耗对应部分；待确认单是否预占必须明确，确认时仍重新校验。
- 回报可能先于 `place_order()` 返回，也可能重复或乱序。订单已终态时，迟来的提交快照不能把它退回 `submitted`。同一标的两笔卖单不能共同占用同一批可卖量。

故障注入至少放在成交、资金、订单、持仓写入及事务提交阶段；断言库与内存完整一致、没有未提交事件、重复恢复不会多记账。若使用 outbox，验证提交后进程退出仍能恢复通知，消费者仍需幂等。

外部券商与 SQLite 不宣称“跨网络 exactly-once”。结果不明时持久化不确定状态并对账，断线不排队重试委托；重连的行情订阅恢复与委托重试分别处理。

## 七、K04：多币种与两端规则一致

电脑端按内部账户与 CNY/USD/HKD 分别记现金、冻结、市值、费用及盈亏；不同币种默认分别展示。已有 `Account` 字段保留明确含义，用兼容扩展或新版本接口表达分币种账户，不能让旧 `cash` 悄悄变成无汇率的混合数。

资金预估、预占、RiskGate、撮合与重启回放调用相同市场费用规则。本轮历史证据：金额 100000 的港股买单，`buy_fee()` 返回 35.00，`fee(..., symbol)` 返回 110.35；先在当前版本复核差异，不把这两个数字当交易所费率规范。

对需要更新的税费、每手数量、市场规则查官方来源，记录生效日期和计算单位，不凭记忆改值。缺少证券级手数时如实显示模拟假设。金额和 B股价格精度采用明确的舍入规则，不能在不同层重复截断造成余额差异。

手机继续是独立本地练习场，不要求回连电脑。通过构建时规则资源、版本号和同一批输入/期望样例对齐两端，不再各手抄一套数字。

验收覆盖 A股主板、创业板、科创板、北交所、沪B、深B、港股：整手/递增单位、零股卖出、T+1/T+0、费用边界、价格精度、资金不足、挂单预占、部分成交、跨日、重启。两端运行同样例，断言预估与成交结算一致；结构字符串检查不能替代行为测试。

## 九、K06：WS 线程、积压与恢复

EventBus 在发布线程内执行订阅回调，WS 不能直接跨线程调用 `asyncio.Queue.put_nowait()`。通过事件循环的线程安全调度方法切换线程，在回调调度和实际队列两处控制积压。

行情可按标的合并最新值；订单、成交、风控事件需要可检测缺口，并通过游标或重新读取持久化快照恢复。前端自动重连成功不等于状态完整，必须完成状态同步后才展示就绪。

测试从真实后台线程发布，覆盖事件循环 debug 模式、慢消费者、队列满、断线/重连、连接关闭时仍有事件、事件突发。测量并断言关键状态恢复一致，丢弃/积压计数可查询，线程和订阅可回收。

## 十、K07：回测子进程、取消与研究快照

回测队列目前在工作线程实例化策略并运行引擎。将策略模块导入、构造、`on_init/on_bar` 全部移入每任务子进程；只把纯数据和约定 IPC 对象传入，适配器实例留在主进程。

覆盖异步与同步 API 路径，不能只隔离其中一种。队列容量和并发上限有限；合作取消无响应后可终止对应任务进程，并清理子孙进程、句柄与 IPC。父进程继续提供 API、交易与其他服务。Windows spawn 入口必须可导入，不能使用只在 fork 下能工作的共享对象假设。

明细分块及时交给持久化层；中断时保留已提交部分并标记 `partial/cancelled/interrupted`，不把不完整指标写成完整结果。

每次运行保存 manifest：策略内容/哈希、参数、证券池、数据分区与复权版本、费用/撮合配置、软件版本、依赖锁摘要。证明相同快照重复运行的业务结果一致，时间和随机 ID 等非确定字段单列。

行为验收：构造/导入异常、死循环、无限日志、子进程退出、取消、重启、队列满、API 同时查询、跨进程恢复明细、相同快照复跑。继续验证下一根 bar 成交、跨周期已收盘数据可见性与同时间多标的权益计算，不能削弱已有无未来数据约定。

## 十一、K08：Parquet、日历、规则证据与缓存

Parquet 写入对同分区串行执行读改写，协调线程与进程；临时文件写在目标同一文件系统，回读校验后原子替换。并发读取始终看到完整旧文件或新文件。按日期选择年/月分区后再读取，复用现有 pyarrow 做列与条件裁剪。

市场日历分别处理 CN/HK，包括假日、半日市及临时休市；调用点读取最新日历，自动路径休市时零外呼。数据不足时显示未知或降级依据，不把单纯工作日启发式冒充已验证开市。

价格规则区分官方规则、可验证证券主数据与启发式推断。简称 N/C、成交价超推算区间等不能独自成为实盘放开价格校验的依据。模拟路径保留清楚的假设与来源，实盘证据不足按项目 fail-closed 合同处理。

拆开日级规则字段与动态价格的缓存；缓存按本次需要的字段是否已取得判断，区分“源不提供”和“尚未取得”。测试首次部分缺失、后续补齐、过期、跨日、来源变化和失败冷却，防止非空缓存锁死一整天。

验收还包括双线程/双进程并发写、替换失败、坏分区、读取范围裁剪；分别构造 A股假日与港股半日市，断言自动外呼次数为零，force 手动路径仍受限速与主机冷却控制。

### 新增 K10：数据、指标与界面契约

先隔离复现以下代码审阅问题，再按是否成立修复：

- Federated 历史非空即命中却未检查日期覆盖，回补可能永远补不到缺口；设置改优先级后缓存中枢未重建。
- Tushare 凭据没有读取界面写入的保险库；Tushare/iFinD 财务长表与财务服务预期的宽表不一致。
- QMT 请求原始或后复权失败时不可静默换成前复权；统一各源成交量/金额单位，查官方合同后转换。

- iFinD 批量实时只解析第一只、内存财务缓存缺 TTL；公开接口按主机冷却的检查与实际外呼之间有竞态。
- 量比选股本地基线排除当前、比较 >=，导出公式却包含当前、比较 >；固定样本 `[100,100,100,100,100,200]`
  和阈值 2，必须让本地与导出公式得到同一结果。
- 盈亏比在一笔盈利加一笔保本时可能除零；港股回测费用分派、分钟/多标的年化与收益曲线时间轴需修正。
- 前端行情切标的时丢弃迟到响应；监控事件刷新合并；下载进度请求失败后继续可恢复轮询；盯盘关闭自动刷新
  后 K 线也必须停止自动请求；官方内外盘与逐笔降级标签随实际 source 变化。
- 手机模拟盘与桌面仍有独立税费/规则，用户文档中的费率不视为交易所规则；先查生效日期，构建规则资源并跨端测样例。
